# Загрузка баз 1С в финансовое ядро (OData-парсер) — памятка сисадмину

## Зачем
Парсер `parser_1c_odata.py` на 1С-сервере тянет платежи из **всех** баз 1С по OData и шлёт
срез на `finance.atamura.group`. Сейчас часть баз не грузится (нет/неверные креды или не
опубликован OData) → по этим дочкам данные о платежах неполные, а финансовый контроль по ним
слепой. **Задача: прописать креды всех баз и убедиться, что парсер их забирает.**

## Файлы (на 1С-сервере)
- `C:\atamura-1c\bases.json` — список баз + креды. **СЕКРЕТ**: не пересылать, не коммитить.
- `C:\atamura-1c\parser_1c_odata.py` — парсер.
- Python: `C:\Users\Администратор\AppData\Local\Programs\Python\Python314\python.exe`.

## Шаг 1. Формат `bases.json`
```json
{
  "months": 3,
  "bases": [
    { "company": "Titan Development",
      "base": "http://localhost/<имя_публикации>/odata/standard.odata",
      "user": "Администратор", "pass": "" }
  ]
}
```
- `base` — URL OData-публикации базы (у каждой базы своя публикация в IIS).
- `user` / `pass` — 1С-логин с правом на OData:
  - логин без пароля → `"pass": ""`;
  - анонимный OData → `"user": "", "pass": ""` (авторизация не шлётся вовсе);
  - обычный логин/пароль → как есть.

## Шаг 2. Публикация OData (если базу парсер пропускает с 404/пусто)
Для каждой такой базы:
1. IIS → опубликовать стандартный интерфейс OData базы (или проверить публикацию и нажать
   «Опубликовать» — сохранённые настройки ≠ применённые).
2. Открыть состав стандартного интерфейса OData (внешняя обработка `odata_setup.bsl`) и включить
   документы: **Контрагенты, ПлатежноеПоручениеИсходящее, ПлатежныйОрдерСписаниеДС,
   РасходныйКассовыйОрдер, ПлатежноеПоручениеВходящее, ПоступлениеТоваровУслуг**.

## Шаг 3. Кодировка (частая грабля!)
`bases.json` сохранять как **UTF-8 БЕЗ BOM**. `Set-Content -Encoding UTF8` в PowerShell 5.1
дописывает BOM → парсер падает на JSON и берёт только одну базу из `.env` (в выводе `баз: 1`,
`(из .env)`). Варианты:
- сохранить без BOM:
  ```powershell
  $p='C:\atamura-1c\bases.json'
  [System.IO.File]::WriteAllText($p,(Get-Content $p -Raw),(New-Object System.Text.UTF8Encoding($false)))
  ```
- либо обновить `parser_1c_odata.py` из репозитория — там уже `encoding="utf-8-sig"`, терпит BOM.

## Шаг 4. Запуск и проверка
```powershell
cd C:\atamura-1c
& "C:\Users\Администратор\AppData\Local\Programs\Python\Python314\python.exe" parser_1c_odata.py
```
Успех: у **каждой** базы `контрагентов: N · оплат исход: N` (не `⚠ ПРОПУСК (401)`), а в конце —
`✅ Отправлено на https://finance.atamura.group/api/ingest: {'ok': True, 'saved': N}`.

Диагностика по строке базы в выводе:
- `⚠ ПРОПУСК (HTTP Error 401)` — креды неверны/не подходят (в т.ч. кириллический «Администратор»
  может требовать доменный вид или отдельного 1С-пользователя);
- `404` / пусто — OData не опубликован или неверный URL `base`.

## Совет по порядку
Сначала пропиши **ОДНУ** проблемную базу (особенно с пустым паролем / кириллическим
«Администратор») и прогони парсер — убедись, что формат кредов проходит. Потом добей остальные
разом. Так возможный 401-нюанс ловится на одной базе, а не на всех.

## Безопасность
`bases.json` держит реальные пароли 1С. Правится **только на сервере**, в git не коммитится
(уже в `.gitignore`), файл никуда не пересылать. Рекомендация: вместо «Администратор» завести
отдельного **read-only 1С-пользователя** для OData (один на все базы) — меньше прав, безопаснее.

## После загрузки
На finance-сервере проверить полноту:
```bash
cd ~/atamura-finance
python3 -c "import server as S; c=S._db(); print('платежей:', c.execute('SELECT COUNT(*) FROM flow').fetchone()[0], '| компаний:', c.execute('SELECT COUNT(DISTINCT company) FROM flow').fetchone()[0])"
```
Число компаний должно вырасти до количества реально работающих дочек.

## Нерешённые базы (низкий приоритет)

`Atree / Atwo / Nuova / NextCity` — стабильно **401 Unauthorized**, перебор не помог:
- пустой Basic (`:`) → 401; `Администратор` (пустой пароль) → 401; `svd/@!0204!@` → 401;
- при этом `WWW-Authenticate: Basic realm="1C:Enterprise 8.3"` (не Windows-auth) — значит нужен
  **конкретный 1С-пользователь** этих баз (смотреть в Конфигураторе → Администрирование →
  Список пользователей той базы), либо в IIS включить им **Anonymous Authentication**.
- **Это пустышки-оболочки: 0 платежей, 0 активности** (в разрезе «по компаниям» их нет). На
  финансовую картину не влияют — оставлены как есть. Догрузить, если станут активными.
